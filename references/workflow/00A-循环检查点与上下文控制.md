# 关关导演｜循环检查点与上下文控制

## 目录

- 目的与运行目录
- 写入时机
- 状态索引
- 计时 Schema 迁移闸门
- 最小读取集
- 节点检查点
- 文件能力降级
- 完成与保留

## 目的

用文件检查点承接长流程状态，使单个 Agent 在下一轮只加载当前工作单元需要的内容。检查点用于减少重复读取和跨轮恢复，不代表已经从当前对话中删除历史上下文。

## 运行目录

宿主具备文件写入能力时，在项目运行目录中使用：

```text
[项目名称]-director/
├── 00-state.yaml
├── _work/
│   ├── N1/scenes/S001.md
│   ├── N3/scenes/S001.md
│   ├── N4/scenes/S001.md
│   ├── N5/groups/S001.md
│   ├── N5/sequences/SG001-A.md
│   └── N5/batches/B001.md
├── history/
└── 01-... 至 06-... 的稳定产物
```

`_work/` 是内部循环缓存，不属于八类用户可见产物。不得把 `_work/`、`00-state.yaml` 或任何运行产物写入 skill 安装目录。

## 写入时机

每个循环单元严格执行：

```text
读取 00-state.yaml
  → 加载当前单元的最小输入集
  → 处理并自检当前单元
  → 写入或覆盖当前单元检查点
  → 更新 00-state.yaml 的位置、摘要、问题和文件索引
  → 到达闸门则等待确认；否则进入下一单元
```

在以下时机写入：

1. 当前场景结构、完整镜头组序列或分镜批次完成自检后。
2. 进入用户闸门前。
3. 用户修改后，用新草稿覆盖当前工作检查点，但不得覆盖上一个已通过稳定版本。
4. 闸门通过后（包括 `auto`、`sample` 或用户确认的 `human`），汇总或更新对应稳定产物，再更新状态中的通过版本。
5. 降级、工具失败或当前回合结束前，写入未决问题、暂定假设和恢复入口。

不要保存完整思考过程、无效尝试或所有历史草稿。每个循环单元只保留当前工作版本；已通过的旧稳定版本才进入 `history/`。

## 状态索引

`00-state.yaml` 只保存短状态和文件指针，不复制产物正文：

```yaml
workflow:
  timing_schema: shot-timing-v2
  current_node: N5
  current_scene: S003
  current_shot_group: SG3-A
  current_batch: B004
  current_revision: null
  review_level: auto
  review_required: false
  auto_pass_reason: null
  retry_count: 1
  resume_action: 生成并校验 SG3-A 的完整镜头序列
iteration:
  scene_order: [S001, S002, S003, S004]
  scene_cursor: 2
  group_order: [SG3-A, SG3-B, SG3-C]
  group_cursor: 0
  batch_cursor: 4
  current_batch_group_ids: []
  completed_scene_ids: [S001, S002]
  designed_group_ids: []
  accepted_group_ids: []
checkpoints:
  current_file: _work/N5/sequences/SG3-A.md
  scene_files:
    S003: _work/N5/groups/S003.md
  sequence_files: {}
  accepted_batches:
    - _work/N5/batches/B001.md
    - _work/N5/batches/B002.md
  revision_files: {}
  upstream_versions:
    analysis: O1-v1
    constitution: O3-v2
    rhythm: O4-v1
    polished_script: O5-v1
context_summary:
  current_unit: 门外脚步声打断读信，信息焦点转向角色反应
  dependencies: [C2, C5, 场景3情节中/情感重/重点展开]
  open_issue_ids: [Q-07]
```

摘要只写恢复所需的事实、决定和约束，不写长篇解释。检查点必须记录其依赖的上游通过版本；版本变化时，将受影响单元标为 `stale`，不能静默沿用。

## 计时 Schema 迁移闸门

进入或恢复 N5、N5R、N6 时，先检查所有将被读取的镜头组序列。当前有效版本固定为 `shot-timing-v2`。以下任一条件成立即为旧计时检查点：

- 文件没有 `timing_schema: shot-timing-v2`。
- 任一镜头缺少按发生顺序记录进入、过程变化、反应和退出状态的 visual_timeline，或缺少标明需转译到九列画面栏的 visual_coverage。
- 仍包含 `duration_budget_seconds`、场景预算或镜头组预算字段。
- 任一镜头缺少 `timing_method`、`duration_seconds` 或可复算的 `duration_basis`。
- 对白镜头缺少完整 `spoken_segments`、有效字符/词数、语速、停顿项或测量证据。
- 动作/空镜缺少事件时间线；静态空镜缺少 `viewer_reads` 或 `exit_condition`。
- `timing_method: measured_audio` 却没有可定位的音频、TTS 或计时工具证据。
- `_work/N5/sequences/` 没有按每个 `group_id` 独立保存的完整序列，或目录中只有 `ALL-groups.md`、`current.md`、`sequence_note` 等摘要聚合文件。

宿主可执行脚本时，使用 `scripts/validate_timing_schema.py [序列文件或目录]` 运行此闸门；退出码非零即为不合格。没有脚本执行能力时，逐项执行同一检查清单，不得降级为只看 `duration_seconds`。

发现旧计时检查点时必须：

1. 将对应序列、所属批次、后续时间码、O7 和 O8 标为 `stale`。
2. 从 `designed_group_ids` 和 `accepted_group_ids` 移除受影响镜头组。
3. 把 `resume_action` 指向最早受影响镜头组的 N5.3 计时遍历。
4. 保留镜头画面、声音和切点作为输入，但删除旧秒数、旧组预算和依赖旧秒数的结论。
5. 忽略旧 O4/O6 中的具体时长区间；它们不能作为迁移后的校验目标。

不得直接在 `_work/N5/batches/` 或 O7 中改时间码来冒充迁移完成，也不得用聚合摘要、批次草案或自然时长汇总证明逐组序列已完成。只有所有受影响组的独立序列重新通过 `shot-timing-v2` 并重新通过 G5，才能重建批次和后续时间码。

## 最小读取集

| 当前工作 | 必须读取 | 默认不重读 |
|---|---|---|
| N1 当前场景 | 原剧本当前场景、项目约束、必要的相邻场景摘要 | 已完成场景全文 |
| N2 命题/宪法 | O1、项目约束；核证时读取对应原文 | 全部场景原文 |
| N3 当前场景 | O1 当前场景结论、O3、原剧本当前场景、相邻场景节奏摘要 | 其他场景完整分析 |
| N4 当前场景 | 原剧本当前场景、O3、O4 当前场景条目 | 其他场景微调正文 |
| N5 镜头组 | S1/S5 当前场景、S2 当前场景结论、S3、S4 当前场景条目、S6 | 其他场景完整分镜 |
| N5 镜头组序列 | 当前镜头组、上一组结尾、下一组叙事入口、相关宪法规则、05B | 其他镜头组完整序列；无需比较方案时不应用 05B 可选方法 |
| N5 分镜批次 | 本批已通过的镜头组序列、上一批末镜、累计时间码、九列规范 | 更早批次全文 |
| N5R 分镜优化 | 用户意见、目标镜头/组、所属批次、相邻镜头、相关 O3/O4/O5 条目、05D | 无关场景和其他已通过批次全文 |
| N6 文件输出 | 完整 O7 和输出规范 | N1-N5 的创作过程文件 |

只有进行跨场呼应、总时长校验、全片意象检查或发现上游冲突时，才扩展读取范围。先读取 `00-state.yaml` 的索引，再定向读取文件；不得为了“保险”每轮重新加载所有产物。

## 节点检查点

| 节点 | 循环单元 | 工作检查点 |
|---|---|---|
| N1 | 场景/序列 | `_work/N1/scenes/Snnn.md` |
| N2 | 候选方向、宪法草案 | `_work/N2/current.md` |
| N3 | 场景/序列 | `_work/N3/scenes/Snnn.md` |
| N4 | 场景/修改单元 | `_work/N4/scenes/Snnn.md` |
| N5 前半 | 场景的节拍与镜头组 | `_work/N5/groups/Snnn.md` |
| N5 中段 | 完整镜头组序列 | `_work/N5/sequences/[组ID].md` |
| N5 后半 | 已格式化分镜批次 | `_work/N5/batches/Bnnn.md` |
| N5R | 分镜讨论与优化请求 | `_work/N5/revisions/Rnnn.md` |
| N6 | 转换与校验轮次 | `_work/N6/current.md` |

场景和批次编号使用固定宽度，按 `S001`、`B001` 递增；镜头组沿用 O6 的组 ID。镜号仍由 O7 连续管理，不能用游标或批次文件名代替镜号。

## 文件能力降级

宿主不能写文件时，在每轮末尾输出一个紧凑对话检查点，字段与 `00-state.yaml` 相同，并只附当前单元结果。下一轮先使用该检查点恢复。不得声称已创建 `_work/` 或状态文件。

## 完成与保留

O8 通过 G6 后将状态标为 `complete`。默认保留 `_work/` 和 `00-state.yaml` 以便追溯，不自动删除；它们不作为正式交付物展示。只有用户明确要求清理时才删除内部缓存。
