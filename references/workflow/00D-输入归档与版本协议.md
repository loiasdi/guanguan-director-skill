# 关关导演｜输入归档与版本协议

## 目的

在进入 N1 前将用户输入固定为可恢复的项目源文件。长流程不得依赖对话上下文记忆来找回剧本。

## 归档时机

1. 第一次收到剧本、梳要、单场或编剧交接包时，先创建项目运行目录和 `input/` 子目录，再进入 N1。
2. 原始剧本、输入约束和交接包只能新增版本，不得覆盖已归档文件。
3. 用户提交修订后，先归档为新版本，再将受影响节点标为 `stale`；不得把修订文字直接覆盖原始剧本。

## 运行目录结构

```text
outputs/[project]-director/
|-- input/
|   |-- script-v001.md          # 原始剧本或当前输入文本
|   |-- constraints-v001.yaml   # 项目约束
|   `-- manifest.yaml           # 版本、来源、场景索引
|-- 00-state.yaml
`-- _work/
```

`script-v001.md` 是 `I1` 原始剧本，不是节点输出。`O1-O5` 是上游节点产物；不再使用会让人误以为“S1-S6 都是节点输出”的命名。

## manifest 最小字段

```yaml
input_version: script-v001
input_mode: script | synopsis | scene | handoff
script_file: input/script-v001.md
constraints_file: input/constraints-v001.yaml
source_label: user | screenwriter-handoff | imported-file
scene_index: []
content_id_scheme: scene-local-v1
archived_at: ISO-8601
```

`scene_index` 至少记录 `scene_id` 、剧本位置、起止行和场景标题。不能解析或提取文字时，必须在 manifest 标记为 `unresolved`，不得声称已完成归档。

## N5 读取硬条件

N5.1 建立 `content_id` 时必须从 `input/script-vNNN.md` 和已确认 O5 合成完整执行稿。N5.3 每次处理镜头组时必须读取该组对应的原剧本切片、O5 切片和 `required_content_ids` 完整原文。只有 ID、段落名或摘要时禁止进入镜头设计，必须回退 N5.1 补齐源文本。

## 无文件能力的降级

宿主无法写文件时，在对话检查点中保留 `input_version` 、完整剧本文本或当前场景原文、场景索引和恢复位置。不得把仅存在于上下文里的文本标记为已归档。
