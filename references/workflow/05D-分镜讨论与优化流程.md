# 第五步 D：分镜讨论与优化流程

## 节点契约

- 节点：`N5R`，属于 N5 的后置优化分支
- 触发：O6/O7 已生成或已通过后，用户指出某个镜头、镜头组、批次或整体分镜需要讨论/优化
- 输入：用户意见、目标稳定 ID、当前已通过版本、相关上游规则
- 输出：优化诊断、候选方案、影响预览；用户确认后生成新的 O6/O7 版本
- 出边：`保留 → 原版本`；`确认镜头修改 → N5.3/G5`；`确认组结构修改 → N5.1-N5.2/G5A`；`确认上游修改 → N2/N3/N4`；`只改格式 → N5.4/N6`

## 1. 先定位，不直接改表

将用户意见绑定到稳定 ID：`scene_id`、`group_id`、`local_shot_id` 或全局 `shot_no`。无法唯一定位时只提出定位问题并保存检查点。若请求涉及时长，先执行 00A 的 `shot-timing-v2` 迁移闸门；旧序列不得作为有效计时输入。

判断修改层级：

| 层级 | 典型请求 | 回退节点 |
|---|---|---|
| 字段层 | 改措辞、声音列、备注、列格式，但不改变任何时长 | N5.4 |
| 单镜头层 | 改景别、角度、运动、画面或声音，但不改变组目的 | N5.3 |
| 镜头组层 | 增删镜头、改变组内顺序或组出口 | N5.3；若边界变了则 G5A |
| 结构层 | 合并/拆分镜头组、改变节拍覆盖或主要叙事目的 | N5.1-N5.2/G5A |
| 上游层 | 修改导演命题、相对节奏重心、项目硬时长约束、剧本动作或人物弧光 | N2/N3/N4 |

单镜头层优化不得暗改已确认的镜头组目的、节拍边界或视听宪法；发现冲突必须升级层级。

任何“重新估时”“缩短/延长镜头”都属于 N5.3 单镜头/镜头组计时修改，不是字段层修改。必须先重建所属序列的计时字段和算式，再由 N5.4 重算时间码；禁止直接编辑 Bnnn/O7 的起止时间。

## 2. 讨论循环

```text
读取当前版本和最小相关输入
  → 复述问题与影响范围
  → 诊断当前设计为何成立/不成立
  → 提出 1-3 个可执行方案（含保留方案）
  → 比较导演一致性、叙事效果、时长、连续性和制作代价
  → 输出影响预览并等待用户选择
  → 用户确认：写入新草稿并进入对应回退节点
  → 用户保留：关闭请求，不改稳定版本
  → 信息不足：登记假设和下一问题，保存恢复入口
```

讨论阶段只展示方案和影响，不把未确认方案写入 O6/O7。每次实质方案最多三轮；仍无法取舍时保留原版本，登记风险，不强行替用户定案。

## 3. 回写与失效范围

用户确认后：

1. 在 `_work/N5/revisions/Rnnn.md` 保存请求、证据、选定方案和影响范围。
2. 生成新草稿版本，保留上一个通过版本到 `history/`。
3. 单镜头修改：重做所属镜头组，重新格式化所属批次并经 G5。
4. 镜头组结构修改：受影响场景及其后续批次标记 `stale`，经 G5A 后重新生成序列。
5. 时长变化：先在 N5.3 重建受影响序列的 `shot-timing-v2` 数据，再从最早受影响批次重算后续时间码；不得只改批次或 O7 时间码。
6. 触及宪法、节奏规划或剧本事实：停止 N5R，回到最早上游节点，禁止在分镜表中偷偷修正。

优化确认后，O6/O7 版本号递增；O8 已存在时必须重新执行 N6/G6。用户未确认时，O8 和稳定 O6/O7 不变。
