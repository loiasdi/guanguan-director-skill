# 第五步：分镜拆解流程

## 节点契约

- 节点：`N5`
- 输入：输入归档中的原始剧本、O1 导演分析、O3 视听宪法、O4 节奏规划、O5 视听化微调稿、项目约束和当前场景内容清单
- 遍历单元：场景队列、镜头组队列、分镜批次
- 修订单元：当前场景结构、当前镜头组完整序列或当前批次格式
- 输出：`05A-镜头组拆解表.md`、`05B-分镜表.md`
- 出边：`G5A 修改 → 当前场景结构`；`G5A 通过 → 当前场景的镜头组队列`；`G5 修改 → 当前镜头组序列/批次格式`；`G5 下一批 → 下一镜头组或场景`；`G5 全部通过 → N6`；`O6/O7 后用户讨论/优化 → N5R`

本文件只负责编排。不要在这里重新定义节拍、镜头设计或九列字段规则；到达对应子节点时再读取规则文件。

N5 使用实际文件映射：`I1 = input/script-vNNN.md`，`O1 = 01-剧本导演分析.md`，`O3 = 02B-全片视听宪法.md`，`O4 = 03-导演节奏规划.md`，`O5 = 04-剧本视听化微调.md`，`I2 = input/constraints-vNNN.yaml`。旧 `S1-S6` 只能作为兼容别名，不能作为唯一输入。

- N5 编排图

- N5.3 镜头组序列循环

## 文件职责

| 文件 | 职责 | 读取时机 |
|---|---|---|
| `05A-镜头组与溯源规则.md` | 从剧本划分戏剧节拍并推导镜头组 | N5.1-N5.2 |
| `05B-镜头组内镜头序列规则.md` | 为已确认镜头组生成完整序列；文件末尾含可选设计参考 | N5.3 |
| `05C-九列分镜数据规范.md` | 把已完成的镜头组序列映射为九列数据 | N5.4 |
| `05D-分镜讨论与优化流程.md` | 已确认分镜的定位、方案比较、影响分析与回写 | O6/O7 生成后用户提出局部或整体修改时 |
| `scripts/validate_timing_schema.py` | 确定性拒绝旧预算、缺字段和无算式的镜头序列 | 每个序列写入后、N5.4 前、恢复旧项目时 |
| `00A-循环检查点与上下文控制.md` | 写入、恢复和最小读取集 | 每个循环单元结束时 |

不得一次性加载全部规则文件。镜头组完成对应审核级别并通过 G5A 后，再读取镜头序列规则；只有需要填写九列时才读取数据规范；只有用户讨论或优化已有分镜时才读取 05D。

## 编排图

```text
进入/恢复 N5：执行 00A 的 shot-timing-v2 迁移闸门
  → 旧序列或旧批次不合格：标记 stale，回到最早受影响组 N5.3
  → 首次进入：从 S5 按剧本顺序建立 scene_order
  → scene_cursor 指向第一个未完成场景
  → N5.1 读取 input/manifest 指向的原剧本当前场景、O1/O3/O4/O5 必要切片和项目约束
  → 读取 05A，建立戏剧节拍表
  → N5.2 从节拍关系推导镜头组
  → 写入 _work/N5/groups/Snnn.md
  → G5A 节拍与镜头组闸门
      ├─ 修改：只回到受影响节拍/镜头组
      ├─ 降级：采用保持因果连续的最小可行分组
      └─ 通过：冻结当前结构并建立 group_order
  → group_cursor 指向当前场景第一个未完成镜头组
  → N5.3 读取 05B，一次生成当前镜头组的完整镜头序列，暂不填写秒数
  → 镜头内容冻结后，在整组内逐镜计算自然时长并汇总组总时长
  → 校验整组覆盖、镜头连接、计时依据和溯源
      ├─ 失败：最多三轮修订整组序列
      ├─ 结构错误：回退 G5A
      └─ 通过：写入序列文件，登记 designed_group_ids/current_batch_group_ids 并推进 group_cursor
  → 未到批次边界：返回 N5.3 处理下一镜头组
  → 到达批次边界：N5.4 读取 05C，映射当前批九列数据
  → 写入 _work/N5/batches/Bnnn.md
  → G5 镜头序列与分镜批次闸门
      ├─ 修改拍法：回到指定镜头组序列，再重建本批
      ├─ 修改字段：只回到本批格式化
      ├─ 发现结构错误：明确回退 G5A
      └─ 通过：冻结本批，将本批组登记为 accepted_group_ids 并判断游标
          ├─ 当前场景仍有组：返回 N5.3
          ├─ 当前场景完成且仍有场景：推进 scene_cursor，返回 N5.1
          └─ 所有场景完成：汇总 O6、O7 并进入 N6

N6 完成后若用户继续讨论 O6/O7，按 05D 进入 N5R；确认修改后必须重新经过受影响的 N5 子节点和 N6。
```

G5A 冻结“拍哪些叙事单元以及为什么这样分组”；G5 冻结“每个具体镜头怎样拍以及如何写入九列”。不得在 G5 阶段暗改已冻结的节拍或镜头组。

## N5.1-N5.2：节拍与镜头组循环

1. 从 `00-state.yaml` 读取当前场景和恢复入口，再从 `input/manifest.yaml` 定位源剧本版本。
2. 只加载当前场景的原剧本切片、O5 当前完整执行稿、O1 当前场景结论、O3、O4 当前场景条目、项目约束和必要内容清单。
3. 读取 `05A-镜头组与溯源规则.md`，先从原始剧本与已确认微调合成完整执行稿，建立逐条必要内容清单，再建立节拍表并推导镜头组。
4. 对照 N3 预规划；允许合并、拆分或改名，但记录差异和理由。
5. 完成规则自检后写入场景检查点，再进入 G5A。

当前节拍或镜头组最多实质修订三轮。第三轮仍无法确定时，记录问题与假设，采用优先保持剧本因果连续、观众理解清晰的最小分组，进入 G5A，不得停滞。

G5A 通过条件：

- 必要行动、台词和声音均被节拍覆盖。
- 必要内容清单中的对白、旁白、画外音、广播、字幕和关键声音均保留完整原文，并已通过 `required_content_ids` 分配到唯一镜头组。
- 每个节拍可追溯到具体剧本范围。
- 每组只有一个主要叙事目的。
- 每组具有宪法依据与节奏依据；不得在镜头设计前填写预计镜数或时长预算。
- 组类型来自节拍关系，不是先套模板。

G5A 通过后，按剧本顺序写入该场景的 `group_order`，并令 `group_cursor = 0`。同时按场景汇总为 O6 `05A-镜头组拆解表.md`。普通场景按 00C 自动继续；关键场景必须先完成人工审核。若关键场景已在 G5A 审核，G5 默认自动，除非出现新的镜头方案冲突、连续性异常或用户点名查看。

## N5.3：镜头组序列循环

1. 先验证将读取的序列符合 `shot-timing-v2`，且每镜存在完整的 visual_timeline 与 visual_coverage。存在旧预算字段、视觉时间线/覆盖字段或计时字段不全时，按 00A 标记失效并把游标回退到最早受影响组；不得直接进入 N5.4。
2. 用 `group_cursor` 取得当前镜头组。没有当前组但 `current_batch_group_ids` 非空时必须进入 N5.4；只有当前批为空且本场全部组都在 `accepted_group_ids` 中时，才可结束本场景。
3. 只加载当前镜头组、上一组结尾、下一组叙事入口和已确认的宪法规则。
4. 读取 `05B-镜头组内镜头序列规则.md`。
5. 只有存在多种合理组织方式时，才使用 05B 文件末尾的“可选设计参考”。
6. 一次生成当前组的完整有序镜头序列；不要把每个镜头建成独立工作流轮次，也不要在内容冻结前填写秒数。
7. 为序列中的每镜保留组 ID、节拍 ID、剧本来源、宪法依据、节奏依据、visual_timeline、visual_coverage 和切镜理由。
8. 内容冻结后执行一次整组内计时遍历：按 05B 固定语速或带证据的测量结果，记录台词字符数、停顿项、台词前后事件、并发动作、空镜读取目标、退出条件和算式，再由单镜自然时长求和得到组总时长。
9. 整组检查内容覆盖、动作-反应、景别连接、声音连续、空间关系、计时依据和制作可行性；不得用 N3/O4 旧区间、相对篇幅或目标片长填满镜头。
10. 通过内部检查后，只能写入一个与当前 `group_id` 一一对应的独立文件 `_work/N5/sequences/[组ID].md`。文件必须包含该组全部镜头、逐镜 `visual_timeline`、`visual_coverage`、计时依据和剧本来源；`ALL-groups.md`、`current.md`、`sequence_note` 或任何只含摘要/批次草案的聚合文件都不是序列检查点，禁止作为 N5.4 或 O7 的数据源。
11. 宿主可运行脚本时，对每个独立序列文件执行 `scripts/validate_timing_schema.py`；失败则留在 N5.3 修复。成功后才将组 ID 加入 `designed_group_ids`，并且只有该组随后通过 G5 才能加入 `accepted_group_ids` 和 `current_batch_group_ids`。设计完成不等于 G5 通过。
12. 在 `group_order` 中的每个组都拥有独立文件且明确记录 G5 通过之前，不得关闭场景、汇总批次或生成 O7/O8；缺少任一组时必须停留在 N5.3/N5.4，而不是用聚合摘要补齐。

这里的循环是“逐镜头组遍历”，不是“逐镜头循环”。当前镜头组的完整序列最多修订三轮；仍无法同时满足规则时，用最清晰的标准镜头组合完成整组，登记取舍后推进到下一组。若问题来自组边界，回退 G5A。

## N5.4：九列格式化与批次循环

1. 再次确认本批每个序列声明 `timing_schema: shot-timing-v2`，visual_timeline/visual_coverage 和计时字段完整；任一失败即回到对应 N5.3。
2. 读取 `05C-九列分镜数据规范.md`。
3. 将当前批中逐一列入 `accepted_group_ids` 的独立镜头组序列按顺序映射为九列，不在格式化时新增创意拍法；不得读取或展开聚合摘要来代替缺失组。
3A. 公开“画面内容”必须按 05C 将内部时间线转译为连续自然语言，不得输出阶段标签，也不得把同一句动作重复扩写；宿主可运行脚本时，执行 `scripts/validate_storyboard_output.py`，失败不得进入 G5 或 N6。
4. 只按 05B 的 `duration_seconds` 延续上一批累计时间码和相邻镜头入口/出口，不在格式化时重新估时。
5. 完成导演一致性、节奏匹配和叙事重心三层检查。
6. 完成导演一致性、节奏匹配和叙事重心三层检查，写入批次检查点并按 00C 进入 G5：普通批次自动通过，抽样批次汇总展示，异常或关键批次暂停人工审核；本批任一组没有独立序列或 G5 证据时不得标记 accepted。

批次边界按以下优先级确定：

1. 当前场景结束时必须关闭当前批次并进入 G5。
2. 长场景预计超过 40 镜时，在完整镜头组边界分批，目标每批约 20-40 镜。
3. 一个叙事序列需要单独确认时，可在其最后一个镜头组后提前关闭批次。
4. 单个镜头组预计超过 40 镜时，该组独立成为一批，不得为了满足数量拆开该组。

批次边界只能落在完整镜头组之后，不能把同一镜头组拆到两个批次。每批声明场景/镜号范围、起止时间码、累计时长、`current_batch_group_ids` 和下一游标。G5 通过后冻结本批，再按游标进入下一镜头组或场景；仅当所有场景的全部 `group_order` 都存在独立序列并出现在 `accepted_group_ids` 后，才可按镜号顺序汇总为 O7 `05B-分镜表.md`。

## 写入与恢复

严格执行 `00A-循环检查点与上下文控制.md`：

- G5A 前写 `_work/N5/groups/Snnn.md`。
- 每个完整镜头组序列通过后写 `_work/N5/sequences/[组ID].md`。
- G5 前写 `_work/N5/batches/Bnnn.md`。
- 每次写入后更新 `00-state.yaml` 的当前位置、上游版本、问题和恢复动作。
- N5R 的讨论草稿写入 `_work/N5/revisions/Rnnn.md`；未确认的候选不得覆盖 O6/O7。
- 下一循环只读取当前检查点和最小输入集，不重新加载已通过批次全文。
- 上游版本变化时，将受影响检查点标为 `stale` 并回到最早受影响子节点。

## 游标初始化与终止

首次进入 N5 时，从 S5 的场景标题和顺序建立 `scene_order`，令 `scene_cursor = 0`。恢复时不得重新初始化，直接使用 `00-state.yaml` 中的游标和完成列表。

游标推进规则：

1. G5A 通过当前场景后建立 `group_order`，令 `group_cursor = 0`。
2. 每个完整镜头组序列通过内部检查后，`group_cursor += 1`。
3. G5 通过当前批后，将 `current_batch_group_ids` 加入 `accepted_group_ids`，清空当前批并令 `batch_cursor += 1`。
4. 当前场景所有 `group_order` 均进入 `accepted_group_ids` 后，将场景加入 `completed_scene_ids`，令 `scene_cursor += 1`，并清空当前场景的 `group_order/group_cursor`。
5. `scene_cursor < scene_order.length` 时返回 N5.1。
6. `scene_cursor == scene_order.length` 且没有未通过批次时结束 N5。

若从 G5 回退某个镜头组序列，从 `designed_group_ids` 和当前批中移除该组，重做并重新格式化本批。若回退 G5A，则把受结构变化影响的序列和批次标为 `stale`，重新建立该场景的 `group_order`。

始终保持以下状态不变量：

```text
accepted_group_ids ⊆ designed_group_ids
current_batch_group_ids ⊆ designed_group_ids
当前场景完成 ⇔ group_order 中每个组都属于 accepted_group_ids
N5 完成 ⇔ 每个 scene_order 场景都属于 completed_scene_ids，且 current_batch_group_ids 为空
```

若用户修改已经通过的旧批次，从 `accepted_group_ids` 移除受影响组，并将该批及其后的批次时间码标为 `stale`，从最早受影响批次恢复。

不得通过“找不到下一个单元”猜测完成；完成必须由游标、完成列表和闸门状态共同证明。

## 完成条件

只有以下条件全部满足才可进入 N6：

- O6 的全部场景通过 G5A。
- O7 的全部批次通过 G5。
- 镜号连续，时间码由 05B 自然时长连续累加；总时长符合硬约束或已登记偏差和回退方案。
- 每镜都能追溯到镜头组和剧本来源。
- O7 不含“待补”“稍后填写”等占位符。

N5 不生成 xlsx；N6 只做确定性文件转换。
